**v1.5.0**
- **UA:** Виправлено серйозну проблему з надійністю: Discord-вебхук за замовчуванням працює в режимі `fire-and-forget` — повертає порожню відповідь одразу, не чекаючи, поки повідомлення реально створено, тож успіх ніколи не перевірявся, і дублі чи збої не можна було відрізнити від вдалої відправки. Telegram-помилки (наприклад, 429 "Too Many Requests") також не логувались, лише показувались користувачу текстом стандартного діалогу. Тепер Discord-запит явно підтверджує доставку (`?wait=true` + перевірка статусу відповіді й тексту помилки), а відправка на кожну платформу обробляється незалежно (раніше спільний `Task.WhenAll` губив інформацію про другу платформу, якщо перша кидала виняток). **EN:** Fixed a serious reliability issue: the Discord webhook defaults to `fire-and-forget` behavior — it returns an empty response immediately, without waiting for the message to actually be created, so success was never actually checked, and duplicates or failures couldn't be told apart from a successful send. Telegram errors (e.g. a 429 "Too Many Requests") also went unlogged, only shown to the user as the default dialog's bare text. The Discord request now explicitly confirms delivery (`?wait=true` + checking the response status and error text), and each platform's send is handled independently (previously a shared `Task.WhenAll` lost information about the other platform whenever the first one threw).
- **UA:** Вікно "📡 Надіслати сповіщення" тепер показує реальний статус відправки окремо для Telegram і Discord ("✓ відправлено" / "✗ не вдалось" з описом помилки / "— не надсилалось") і не закривається автоматично, якщо хоч одна платформа не підтвердила успіх. Усі результати (успіх з ID підтвердження чи повна помилка) логуються в `logs/` — раніше логувався лише намір відправити, а не фактичний результат. **EN:** The "📡 Send Notification" window now shows a real send status separately for Telegram and Discord ("✓ sent" / "✗ failed" with the error / "— not sent") and no longer auto-closes if any platform didn't confirm success. Every result (success with a confirmation ID, or the full error) is logged to `logs/` — previously only the send intent was logged, not the actual outcome.
- **UA:** Додано захист від дублів: повторне натискання "Надіслати" без зміни вмісту для платформи, яка вже підтвердила успіх минулого разу, запитує окреме підтвердження перед повторною відправкою туди — за замовчуванням ця платформа пропускається. Зміна тексту чи вкладень скасовує захист (вважається новим повідомленням). **EN:** Added duplicate-send protection: pressing "Send" again without changing the content, for a platform that already confirmed success last time, asks for a separate confirmation before sending there again — by default that platform is skipped. Changing the text or attachments clears the protection (treated as a new message).
- **UA:** У повністю ручному режимі додано лічильник символів під кожним текстовим полем — для Telegram межа залежить від наявності вкладення (4096 без нього, 1024 з ним — підпис коротший), для Discord завжди 2000. Перевищення ліміту блокує відправку на цю платформу: якщо лишається хоча б одна платформа без перевищення, перед відправкою з'являється запит на підтвердження часткової відправки лише туди; якщо валідної платформи не лишається — відправка скасовується повністю. **EN:** Fully manual mode now has a character counter under each text field — for Telegram the limit depends on whether an image is attached (4096 without, 1024 with — a caption is shorter), for Discord it's always 2000. Exceeding the limit blocks sending to that platform: if at least one platform stays within its limit, a confirmation prompt offers a partial send to just that platform; if no valid platform remains, the send is cancelled entirely.
- **UA:** У "⚙️ Налаштування" → Discord додано "Збережені ролі Discord" — список будь-якої кількості пар назва+ID (той самий підхід, що й у додаткових каналах). У генераторі згадок вікна ручної відправки для типу "Роль" ці ролі з'являються як список швидкого вибору — разом з основною роллю з поля Discord Role ID (автоматичний пінг у шаблонних сповіщеннях), яка потрапляє туди автоматично, позначена як "Роль зі сповіщень (основна)", без потреби дублювати її вручну. **EN:** "⚙️ Settings" → Discord now has "Saved Discord roles" — a list of any number of name+ID pairs (the same approach as the additional channels). In the manual-send window's mention generator, for the "Role" type these roles appear as a quick-pick list — together with the primary role from the Discord Role ID field (the automatic ping in template notifications), which is included there automatically, labeled "Role from notifications (primary)", with no need to duplicate it by hand.
- **UA:** Над текстовими полями ручного режиму (Telegram і Discord) додано кнопки форматування (жирний/курсив/підкреслення/закреслення/код/спойлер/посилання) — застосовують код до виділеного тексту, або вставляють пару тегів/символів на місці курсора й ставлять курсор між ними, якщо нічого не виділено. **EN:** Formatting buttons (bold/italic/underline/strikethrough/code/spoiler/link) were added above the manual-mode text fields (Telegram and Discord) — they apply the markup to the selected text, or, if nothing is selected, insert a pair of tags/symbols at the caret and place the caret between them.
- **UA:** Галерея зображень у ручному режимі тепер підтримує зміну порядку (кнопки ◀/▶ або перетягування миші) та перегляд у повний розмір по кліку на мініатюру. Порядок у галереї визначає порядок у фактичному повідомленні (sendPhoto/sendMediaGroup для Telegram, multipart-запит для Discord). **EN:** The image gallery in manual mode now supports reordering (◀/▶ buttons or mouse drag) and a full-size preview on thumbnail click. The gallery order determines the order in the actual message (sendPhoto/sendMediaGroup for Telegram, the multipart request for Discord).
- **UA:** У "✏️ Редакторі шаблонів" під кожним полем додано лічильник символів: для Telegram — межа 4096 (текст повідомлення), для Discord — окремо 256 (заголовок embed) і 4096 (текст embed), оскільки це різні поля з різними лімітами API, а не єдиний ліміт 2000, що й у ручному режимі. Перевищення позначається червоним і блокує кнопку "Зберегти" до скорочення тексту. **EN:** The "✏️ Template Editor" now shows a character counter under each field: 4096 for Telegram (message text), and for Discord separately 256 (embed title) and 4096 (embed description), since these are distinct API fields with distinct limits rather than the single 2000-character limit used in manual mode. Exceeding a limit turns it red and blocks the "Save" button until the text is shortened.
- **UA:** Вікно "📡 Надіслати сповіщення" тепер перевіряє з'єднання з увімкненими платформами ще ДО натискання "Надіслати" — автоматично під час відкриття вікна й повторно за кнопкою 🔄. Для Telegram це `GetMe` (чи дійсний токен бота) і `GetChat` (чи саме цей бот бачить саме цей канал); для Discord — `GET` на URL вебхука (чи дійсний і не відкликаний). Обидві перевірки — одноразовий read-only запит за відкриття вікна чи натискання кнопки, без циклів і повторів, нічого не публікують і не видно підписникам каналу. **EN:** The "📡 Send Notification" window now checks connectivity with the enabled platforms BEFORE "Send" is pressed — automatically when the window opens, and again via the 🔄 button. For Telegram this is `GetMe` (is the bot token valid) and `GetChat` (can this specific bot see this specific channel); for Discord it's a `GET` on the webhook URL (is it valid and not revoked). Both checks are a single read-only request per window open or button click, with no loop or repetition, and post nothing visible to channel subscribers.

File-browser selection only, with thumbnails and a remove button per file; a soft warning appears for files over 10 MB. Discord receives files via a multipart webhook request, Telegram via `sendPhoto` (single image, with a caption) or `sendMediaGroup` (2-10, caption on the first only). Confirmed with a real send to both platforms.

**v1.3.0**
- **UA:** Повернуто повністю ручний режим — перемикач "✍️ Повністю ручний режим (без шаблону)" у вікні "📡 Надіслати сповіщення". Вимикає будь-яку підстановку шаблону: окремі текстові поля для Telegram (HTML-форматування) і Discord (Markdown, теги ролей/користувачів) — відправляється рівно те, що введено. **EN:** Brought back fully manual mode — a "✍️ Fully manual mode (no template)" toggle in the "📡 Send Notification" window. Disables all template substitution: separate text fields for Telegram (HTML formatting) and Discord (Markdown, role/user mention tags) — sends exactly what was typed.
- **UA:** У ручному режимі додано необов'язкові поля дати/часу, що генерують готові до копіювання позначки часу — читабельний рядок для Telegram і `<t:...:F>` тег для Discord (той самий формат, що й в автоматичних Upcoming-шаблонах). **EN:** Manual mode now has optional date/time fields that generate ready-to-copy timestamp snippets — a readable string for Telegram and a `<t:...:F>` tag for Discord (the same format used in the automatic Upcoming templates).
- **UA:** У ручному режимі додано генератор згадок Discord: вводиться лише ID, а готовий код (`<@&ID>` для ролі, `<@ID>` для користувача, `<#ID>` для каналу) генерується нижче з кнопкою копіювання — за тим самим принципом, що й позначки часу. Набирати кутові дужки й `&` вручну більше не потрібно. Введений замість ID цілий скопійований тег відхиляється (ID у Discord — це лише цифри), щоб у повідомлення не потрапив вкладений сам у себе тег. **EN:** Manual mode now has a Discord mention generator: you enter just the ID and the finished code (`<@&ID>` for a role, `<@ID>` for a user, `<#ID>` for a channel) is generated below with a copy button — the same principle as the timestamps. No more typing angle brackets and `&` by hand. A whole copied tag pasted instead of an ID is rejected (a Discord ID is digits only), so no self-nested tag ends up in the message.
- **UA:** Додано підтримку кількох іменованих каналів Discord. Назви задає користувач, кількість довільна — нічого не захардкоджено. У вікні надсилання типово використовується основний канал; галочка «Надіслати в інший канал Discord» відкриває список, і сам блок з'являється лише якщо каналів справді більше одного. Автоматичні сповіщення завжди йдуть в основний канал. **EN:** Added support for multiple named Discord channels. The names are set by the user and the count is arbitrary — nothing is hardcoded. The send window uses the primary channel by default; a "Send to a different Discord channel" checkbox reveals the list, and the block itself appears only when there really is more than one channel. Automatic notifications always go to the primary channel.
- **UA:** Часовий пояс для всіх дат трансляції більше не захардкоджений на Київ у трьох місцях коду — тепер це поле налаштувань (`TimeZoneId`), яке при першому запуску автоматично підставляється з системної зони, а існуючі інсталяції без цього поля й далі коректно працюють за Києвом (зворотна сумісність). **EN:** The timezone used for all stream dates is no longer hardcoded to Kyiv in three places in the code — it's now a settings field (`TimeZoneId`) that's auto-filled from the system's zone on first run, while existing installs without this field keep working correctly on Kyiv time (backward compatible).
- **UA:** Усі 4 поля дати/часу (шаблонний і ручний режими) отримали кнопку 📅 (календар), 🕐 (вибір години/хвилини) і ⏱ (підставити поточні дату/час у налаштованому часовому поясі) — набирати вручну більше не обов'язково, хоча й досі можна. **EN:** All 4 date/time fields (template and manual modes) got a 📅 (calendar), 🕐 (hour/minute picker), and ⏱ (fill in the current date/time in the configured timezone) button — manual typing is no longer required, though still fully supported.
- **UA:** Додано опціональний запасний шлях через YouTube Data API на випадок, коли RSS-фід лежить тривало. Кнопка 🔑 з'являється **тільки** в банері помилки (у нормальному стані її немає) і перед запуском питає підтвердження з явною ціною: ~202 одиниці добової квоти проти 0 у безкоштовного RSS. Шлях складається з трьох запитів — плейлист завантажень (звичайні відео та Shorts), `search.list eventType=upcoming` (заплановані трансляції) і `eventType=live` (активна), бо самого плейлиста завантажень для запланованих трансляцій недостатньо. **EN:** Added an optional YouTube Data API fallback for when the RSS feed is down for a longer stretch. The 🔑 button appears **only** in the error banner (it doesn't exist in the normal state) and asks for confirmation with an explicit price before running: ~202 daily quota units versus 0 for the free RSS feed. The path is three requests — the uploads playlist (regular videos and Shorts), `search.list eventType=upcoming` (scheduled streams) and `eventType=live` (the active one), because the uploads playlist alone isn't enough for scheduled streams.
- **UA:** ⚠️ На момент релізу не протестовано в реальних умовах: надсилання в альтернативний канал Discord і щойно описаний запасний шлях через YouTube Data API. Обидва реалізовані й перевірені статично, але живого проходу не мали. Перше протестовано і виправлено в v1.3.1, друге лишається непротестованим — див. попередження на початку README. **EN:** ⚠️ Untested in real conditions at release time: sending to an alternative Discord channel and the YouTube Data API fallback described above. Both were implemented and statically verified, but never had a live run. The first was tested and fixed in v1.3.1; the second remains untested — see the warning near the top of the README.
- **UA:** Запит до RSS-фіду YouTube тепер повторюється до 3 разів зі зростаючою паузою, якщо фід віддає 5xx або 429 (сервіс періодично робить це на цілком валідний ChannelId). Помилки на кшталт 404 не повторюються — вони означають неправильний ChannelId, і повтори його не виправлять. Додано явний User-Agent і спільний HttpClient замість створення нового на кожен запит. **EN:** The YouTube RSS feed request is now retried up to 3 times with growing back-off when the feed answers 5xx or 429 (the service does this intermittently even for a perfectly valid ChannelId). Errors like 404 are not retried — they mean a wrong ChannelId, which retries won't fix. Added an explicit User-Agent and a shared HttpClient instead of creating a new one per request.
- **UA:** Виправлено: збій мережі або вичерпана квота YouTube Data API більше не спустошують вікно надсилання. Раніше виняток відкидав і локальний кеш, а повідомлення про помилку було приховане разом зі згорнутою панеллю вибору — вікно виглядало просто порожнім без пояснень, і причина нікуди не логувалась. Тепер список показується з локального кешу, у вікні з'являється помітний банер з кнопкою ↻ (повторити без перезапуску), повний стектрейс пишеться в `logs/`, а модальне вікно з'являється лише коли кеш теж порожній — тобто працювати справді нічим. **EN:** Fixed: a network failure or an exhausted YouTube Data API quota no longer empties the send window. Previously the exception discarded the local cache too, and the error message was hidden along with the collapsed picker panel — the window just looked blank with no explanation, and the cause was never logged. Now the list is served from the local cache, a clearly visible banner with a ↻ (retry without restarting) button appears, the full stack trace goes to `logs/`, and a modal dialog is shown only when the cache is empty as well — i.e. when there is genuinely nothing to work with.

- **UA:** Нове вікно "⚙️ Налаштування" — зміна комбінації платформ будь-коли, без перезапуску; вимкнення платформи лише призупиняє її використання й не стирає збережені ключі/токени в `appsettings.json`. **EN:** New "⚙️ Settings" window — change the platform combination anytime, without restarting; disabling a platform only pauses its use and doesn't wipe its saved keys/tokens in `appsettings.json`.
- **UA:** Секретні поля приховані за замовчуванням. **EN:** Secret fields are masked by default.

**v1.0.1 / v1.0.0**
- **UA:** Перший реліз — автовиявлення контенту YouTube, відправка в Telegram і Discord. **EN:** Initial release — YouTube content auto-detection, Telegram and Discord dispatch.
